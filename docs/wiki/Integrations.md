# Integrations

Viable uses provider-neutral domain boundaries. Integrations should add evidence or execution capability without becoming the product's source of truth.

## Webdog / Website Watch

Webdog informed Website Watch and remains an optional integration target. Viable currently supports strict Webdog-compatible manual evidence import, not a live Webdog dependency.

Generated Webdog summaries are suggestions, not reviewed evidence. Webdog credentials, sessions, hosted database state, notification destinations, and private monitored content do not belong in Viable source or fixtures.

See the [Webdog assessment](https://github.com/MythologIQ-Labs-LLC/Viable/blob/main/docs/integrations/webdog-website-monitoring.md).

## ViMax / Video Production

ViMax is an optional, removable video-production compatibility target. Viable produces provider-neutral packages and can import structured artifacts, but does not currently treat the upstream interactive TUI as a stable machine execution API.

See the [ViMax assessment](https://github.com/MythologIQ-Labs-LLC/Viable/blob/main/docs/integrations/vimax-video-generation.md).

## Future adapter families

The approved product model leaves room for:

- website and competitor monitoring;
- search and SEO/AEO evidence;
- social and community signals;
- publishing and delivery adapters;
- analytics providers;
- repository traffic/write APIs;
- CRM, relationship, lead, and opportunity adapters;
- email/newsletter providers;
- additional model and media providers.

Each integration must preserve source identity, provenance, failure state, approval boundaries, credential isolation, and provider terms.
