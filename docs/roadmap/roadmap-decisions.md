# Viable Roadmap Decisions

## 2026-07-15: Viable is a marketability operating system

Viable is not centered on event discovery. Event monitoring is one opportunity-signal capability inside a larger product loop covering product truth, market intelligence, positioning, content, website and search readiness, public repository growth, approved distribution, lead capture, sales enablement, measurement, and product learning.

## 2026-07-15: Public repository growth is first-class

Public repositories are product surfaces and distribution channels. Viable will support repository readiness, release planning, community health, launch orchestration, traffic and adoption measurement, and commercial conversion paths.

Viable will not guarantee GitHub Trending or automate fake engagement.

## 2026-07-15: ViMax is an optional production adapter

ViMax is a candidate orchestration backend for script, storyboard, image, video, consistency, and assembly workflows.

Viable retains authority for campaign intent, product claims, source evidence, asset rights, credentials, approval, final asset state, publishing, and measurement.

The initial integration is a manual production-package export. A local CLI or worker adapter follows only after security, packaging, cost, provider, cancellation, rights, and recovery requirements are met.

## 2026-07-15: Manual activation precedes broad publishing automation

Viable must deliver a complete marketability loop through exports, reviews, scheduling, and outcome capture before restricted or paid platform APIs become dependencies.

## 2026-07-15: Product truth precedes generated content

The first application vertical slice after the sanitized source migration is Product Truth and Marketability Assessment. Campaigns, content, outreach, repository recommendations, and video scripts must use the same verified product record and claims ledger.
